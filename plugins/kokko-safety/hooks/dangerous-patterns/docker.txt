# docker.txt - container operations that destroy PERSISTENT state.
#
# THE LINE IS VOLUMES, NOT CONTAINERS.
#
# Containers and images are rebuildable by definition -- that is the entire
# premise of a devcontainer. `docker stop`, `docker compose down`,
# `docker rm -f`, `docker image prune -a` and `docker builder prune` are
# routine, and this file used to deny every one of them. Worse, it denied
# `docker image prune -a` -- the exact command the kokko devcontainer's own
# disk-space warning tells you to run when the Colima VM fills up. A guard that
# blocks the remedy printed by its own sibling tooling is not a guard.
#
# Volumes are different: they hold the docker-in-docker image store, Claude
# Code conversation state and VS Code server state, none of which come back.
# See kokko-devcontainer MANAGING.md -> Disk management.
#
# Swarm/service/secret removal is kept because it acts on a live orchestrator,
# not on local scratch state.
#
# Patterns are anchored to a command position and matched case-sensitively by
# lib/patterns.sh.

# --- Named volume deletion ---
docker[[:space:]]+volume[[:space:]]+(rm|remove|prune)
podman[[:space:]]+volume[[:space:]]+(rm|remove|prune)
nerdctl[[:space:]]+volume[[:space:]]+(rm|remove|prune)

# --- Prunes that sweep volumes in with everything else. `docker system prune`
# --- alone is safe and useful; `--volumes` / `-a --volumes` is not.
docker[[:space:]]+system[[:space:]]+prune[[:space:]]+.*--volumes
podman[[:space:]]+system[[:space:]]+prune[[:space:]]+.*--volumes

# --- Compose teardown that takes the volumes with it. Plain `down` is fine.
docker[[:space:]]+compose[[:space:]]+down[[:space:]]+.*(-v([[:space:]]|$)|--volumes)
docker-compose[[:space:]]+down[[:space:]]+.*(-v([[:space:]]|$)|--volumes)

# --- Live orchestrator state ---
docker[[:space:]]+swarm[[:space:]]+leave
docker[[:space:]]+node[[:space:]]+rm
docker[[:space:]]+service[[:space:]]+(rm|remove)
docker[[:space:]]+stack[[:space:]]+(rm|remove)
docker[[:space:]]+secret[[:space:]]+rm
docker[[:space:]]+config[[:space:]]+rm
